# Словарь марок, синонимов и сокращений

Задача #5. Отвечает на вопрос: как понять, что «приточная установка» в проекте
и «П1» на чертеже — это одно и то же.

```bash
python dictionary/build.py
```

```bash
python dictionary/check.py --object OBJ-TYUMENSKAYA-5-GOLD-SEED --gaps 20
```

| Файл | Что это |
|---|---|
| `terms.jsonl` | сам словарь, 188 записей и 420 вариантов написания |
| `build.py` | сборка из трёх источников |
| `match.py` | поиск терминов в тексте по основам слов |
| `check.py` | покрытие по корпусу и очередь на пополнение |

## Откуда берутся записи

**Легенда к матрице**, 103 записи. Расшифровки марок чертежей, разделов проектной
документации и единиц измерения. Слова самого организатора, доверие высшее.

**Предметная часть**, 19 записей, внесена руками. Легенда описывает разделы
документации, а нарушения — оборудование внутри помещений, и этого в ней нет.
Сюда попали приточные и вытяжные системы, тёплые полы, венткамеры и организационные
формы юридических лиц.

**Корпус**, 66 записей. Наименования помещений из уже собранных экспликаций.
Идут как наблюдения: они говорят, как пишут на практике.

## Почему точное сравнение строк не годится

Это главное, что выяснилось на корпусе, и ради этого написан `match.py`.

**Ё и Е.** В словаре «тёплый пол», в документах «теплые полы». Точное вхождение
давало ноль страниц, хотя термин есть.

**Русская морфология.** В словаре «вытяжная вентиляция», в документах «вытяжной
вентиляцией», «вытяжные установки», «приточно-вытяжная». Точное вхождение давало
ноль, на деле термин встречается на 95 страницах.

Поэтому сравнение идёт по основам: каждое значимое слово усекается, и термин
считается найденным, когда все его основы есть на странице. Это грубее лемматизации,
зато не требует словаря форм.

Переход на основы поднял четыре термина эталонных нарушений с нуля до реальных чисел:

| Термин | Точное вхождение | По основам |
|---|---|---|
| приточная установка | 0 страниц | 48 |
| вытяжная вентиляция | 0 | 95 |
| тёплый пол | 0 | 4 |
| венткамера | 21 | 26 |

## Как пополнять

`check.py` печатает две вещи. Записи словаря, которые в корпусе не встретились:
их надо либо чинить, либо признать неприменимыми к объекту. И частые основы слов
корпуса, которых в словаре нет: это очередь на пополнение, и она важнее первой половины.

Так были добавлены кондиционирование, вентилятор, воздуховод, отопительный прибор,
огнезадерживающий клапан и марка ВЕ.

## Что дальше

Марки оборудования с номером (П5, В17, ОЗК3) распознаются по образцу, а не по списку:
в `terms.jsonl` у таких записей поле `mark_pattern`. Связку конкретного номера
с конкретным помещением строит задача #4.

Словарь собран по одному объекту. На остальных наверняка всплывут иные написания,
и `check.py` для того и нужен, чтобы это увидеть, а не угадывать.
