# Правила Матрицы

Правила сверки по Матрице контроля — закрытая часть сервиса, в открытом репозитории их нет.
Здесь лежат манифест с версией и суммами файлов (`manifest.json`) и скрипт, который выкачивает
правила из закрытого репозитория по токену (`fetch.py`). Токен выдаёт команда.

## Как получить правила

Для сервиса нужен только токен. Положите рядом с `docker-compose.yml` файл `.env` со строкой

```
RULES_TOKEN=<токен>
```

и соберите сервис: `docker compose up --build`. Можно запустить `./build.sh`, он спросит токен сам.
Сборка воркера выкачает правила, сверит суммы SHA-256 с `manifest.json` и положит правила в образ.
Токен идёт секретом сборки и в образ не попадает. Нужен Docker Compose 2.7 или новее.

Для конвейера без сервиса и для тестов правила кладутся в эту папку:

```bash
python rules/fetch.py            # токен из RULES_TOKEN или из .env; нет ни там, ни там — спросит
python rules/fetch.py --check    # проверить, что правила на месте и суммы сходятся
```

## Что внутри

| Файл | Содержимое |
|---|---|
| `matrix_queue1.json` … `matrix_queue5.json` | правила пяти очередей Матрицы: 132 параметра, у 101 проверка реализована |
| `provisional/q1.json` … `q5.json` | черновики правил ещё для 16 параметров: их нарушения идут в протокол гипотезами, в файл сдачи — только решением инспектора |
| `specialist_guidance.json` | решения специалиста по видам находок свободного поиска |

Правило параметра задаёт, где искать значение (подписи, разделы, документы-источники), как
сравнивать стадии и с каким допуском, основание из Матрицы и пояснение для инспектора. Движок,
который исполняет правила, открыт: `pipeline/matrix_rules.py` и соседние модули, описание —
в [pipeline/README.md](../pipeline/README.md).

Версия правил закреплена в `manifest.json` коммитом закрытого репозитория. Правка правил там
на собранный сервис не влияет, пока манифест не обновлён. Файл с другой суммой скрипт
не перезаписывает без ключа `--force`.
