# Инспектор ИИ

Сервис автоматизированной сверки проектной, рабочей и исполнительной документации
объектов капитального строительства. Кейс № 10 Мосстройнадзора, ЛЦТ 2026.

## Сервис

Правила Матрицы в открытый репозиторий не входят: сборка выкачивает их по токену, который
выдаёт команда ([rules/README.md](rules/README.md)). Положите токен в `.env` и соберите сервис:

```bash
cp .env.example .env          # впишите RULES_TOKEN=<токен>
docker compose up --build
```

То же одной командой, скрипт спросит токен сам:

```bash
./build.sh
```

Нужен Docker Compose 2.7 или новее. Веб-клиент — http://localhost:8080, API со Swagger —
http://localhost:3000/api/docs. Папку объекта целиком можно провести из командной строки:

```bash
python tools/upload_object.py --folder "data/Новослободская" --object-id OBJ-NOVOSLOBODSKAYA
```

Загрузчик принимает файлы любого размера (учётная запись `admin`); лимиты ТЗ, 50 МБ на файл
и 200 МБ на пакет, действуют при загрузке в браузере.

Состав, статусы, лимиты и расхождения с ТЗ — в [service/README.md](service/README.md).

## Что здесь

| Каталог | Содержимое |
|---|---|
| `service/` | веб-сервис: API на Node.js, воркер на Python, веб на React, схема базы, мониторинг |
| `pipeline/` | конвейер: реестр, чтение страниц, основная надпись, правила Матрицы, проекция в сдачу ([описание](pipeline/README.md)) |
| `rules/` | Матрица контроля: 132 параметра пятью очередями. Сами правила закрыты и выкачиваются по токену ([описание](rules/README.md)) |
| `contracts/` | JSON-схемы: формат сдачи, находка, реестр документов, постраничный индекс, перечни значений |
| `tests/` | проверки конвейера: запускаются как `python tests/test_<тема>.py`, без внешних библиотек |
| `tools/` | загрузка объекта в сервис, восстановление имён файлов корпуса |
| `dictionary/` | словарь марок, синонимов и сокращений: «приточная установка» и «П1» — одно и то же |
| `docs/extracted/` | данные организатора, которые читает конвейер: каталог 132 параметров Матрицы, реестры документов объектов, исключённые из корпуса файлы |
| `deploy/` | надстройка compose для облачного стенда: TLS и автозапуск |

`build.sh` собирает и поднимает сервис одной командой, `.env.example` — образец настроек.

Корпус документов в репозиторий не входит: он раздаётся организатором и занимает
несколько гигабайт. Пути к нему настраиваются локально.

## Новый объект

Оценка организатора пойдёт на новом закрытом объекте. Для нового объекта в коде ничего
править не нужно: всё, что меняется от объекта к объекту, задаётся ключами команд
и переменными окружения.

**Загрузка.** Папку объекта загружают в веб-клиенте или загрузчиком: он сам создаст объект,
разложит файлы по стадиям и дождётся протокола. Тома больше лимитов браузера — только загрузчиком.

```bash
python tools/upload_object.py --folder "/путь/Новый объект" --object-id OBJ-NEW
```

**Реестр организатора.** Если к объекту есть реестр (`document_manifest.jsonl` или
`files_index.jsonl`), файлы получат официальные идентификаторы для сдачи; без него идентификаторы
будут локальными (`L0001`). Файл узнаётся по SHA-256 содержимого, а не по пути. Реестр кладут рядом
с `docker-compose.yml`, монтируют в воркер и называют переменной:

```yaml
  worker:
    volumes:
      - ./manifests:/app/manifests:ro
```

```bash
INSPECTOR_MANIFESTS=/app/manifests/files_index.jsonl docker compose up -d worker
```

**Стадия и раздел** берутся из названий папок (`ПД`, `РД`, `ИД`, «Проектная документация»,
`АОСР`…), а если папка стадию не называет — из шифра в имени файла. Документ без стадии в сравнении
стадий не участвует. Сколько таких, видно в блоке «Готовность объекта», стадию можно задать руками
на экране объекта и пересобрать протокол.

**Имена в кодировке cp866** («€§г¬аг¤­ п» вместо названия улицы) лечатся до загрузки:
`python tools/fix_filenames.py --root "/путь/Объект"` покажет план, с ключом `--apply` переименует
и запишет карту отката.

**Без сервиса** объект задаётся ключом `--root`:

```bash
python -m pipeline.cli run --object OBJ-NEW --root "/путь/Новый объект" --name "Новый объект"
```

## Что включено по умолчанию

| Что | По умолчанию | Как изменить |
|---|---|---|
| Правила Матрицы | пять очередей: 132 параметра, у 101 проверка реализована; черновики ещё для 16 параметров дают гипотезы | `PIPELINE_PROVISIONAL=0` — без черновиков |
| Чтение страниц | текстовый слой у всех страниц, распознавание Tesseract на сканах и в углах листов, модель прицельно: сканы без текста и чертежи, у которых в слое меньше 40 слов | способ выбирает инспектор при загрузке; по умолчанию `PIPELINE_READING_MODE=model` |
| Модель | своя модель в контуре заказчика по адресу `PIPELINE_MODEL_URL`; если модель не настроена, чтение понижается до распознавания, и инспектор видит уведомление | `PIPELINE_MODEL=0` — без модели |
| Проход по чертежам | вопрос модели по листу о значении, которого нет в тексте: до 40 новых вопросов на объект, ответы кешируются | `PIPELINE_VLM=0` — выключить |
| Лимиты приёма файлов | 50 МБ файл, 200 МБ пакет (ТЗ) в браузере; загрузчик — без лимита | `MAX_FILE_MB`, `MAX_PACKAGE_MB`; лимит nginx следует за пакетом |
| Передача в ИАИС «РиН» | заглушка на стенде | `IAIS_URL` |
| Мониторинг | выключен | `docker compose --profile monitoring up` |

## Быстрый старт

Конвейер без сервиса: Python 3.11 или новее, зависимости и Tesseract отдельной программой
(`brew install tesseract tesseract-lang` или `apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng`).

```bash
pip install -r requirements.txt
python rules/fetch.py          # правила по токену: из RULES_TOKEN, из .env или спросит
python -m pipeline.cli objects
```

Провести объект целиком — реестр, страницы, основная надпись, акты, правила Матрицы
и файл сдачи (#8). Чтение кешируется, поэтому повторный прогон дешёвый:

```bash
python -m pipeline.cli run --object OBJ-TYUMENSKAYA-5-GOLD-SEED
```

Проверки конвейера — отдельными скриптами; проверкам правил нужны выкачанные правила:

```bash
for t in tests/test_*.py; do python "$t" > /dev/null || echo "СБОЙ $t"; done
```

## Что уже решено

**Конвейер чтения.** Текстовый слой читается у всех страниц, Tesseract распознаёт сканы и углы
листов с основной надписью, обозначения систем на листах без слоя дочитываются по форме
глифов-штрихов. Модель смотрит только туда, где текста нет: сканы без текстового слоя и чертежи
с тонким слоем. По умолчанию инспектору предлагаются открытые модели Qwen, которые поднимаются
на одной видеокарте внутри контура заказчика.

**Форма находки.** Продиктована перечнем нарушений организатора: лист проектной
документации против чертежа рабочей, адресовано номером помещения. Подробности
в [контрактах](contracts/README.md).

## Настройки

Всё, что зависит от контура, задаётся в `.env` рядом с `docker-compose.yml`. Образец —
`.env.example`, сам `.env` в репозиторий не попадает.

| Переменная | Что задаёт |
|---|---|
| `RULES_TOKEN` | токен доступа к закрытым правилам Матрицы, нужен для сборки |
| `PIPELINE_MODEL_URL`, `PIPELINE_MODEL_NAME` | адрес и имя своей модели в контуре заказчика: API в формате OpenAI chat/completions |
| `PIPELINE_MODEL_CHOICES` | какие модели предлагать инспектору на экране загрузки |
| `INSPECTOR_OPENROUTER_API_KEY` | ключ модели, если адрес его требует |
| `AUTH_USERS` | учётные записи `логин:пароль:роль`; по умолчанию стендовые `inspector`, `admin`, `expert` |
| `MAX_FILE_MB`, `MAX_PACKAGE_MB` | лимиты загрузки в браузере |

Полный перечень переменных — в [service/README.md](service/README.md).
