# Облачный стенд

Здесь две надстройки над `docker-compose.yml`. Стенд с видеокартой и своей моделью —
`docker-compose.release.yml`, как его поднять, описано в README в корне репозитория. Ниже — облачный стенд.

Тот же `docker compose`, что и на ноутбуке, плюс Caddy с автоматическим TLS. Отдельного
кода для облака нет: надстройка `deploy/docker-compose.demo.yml` добавляет один контейнер
и автозапуск, всё остальное берётся из основного файла.

## Что нужно

- машина с Docker и Docker Compose 2.7 или новее; стенд команды работает на 8 ядрах, 32 ГБ
  памяти и диске 200 ГБ;
- домен, у которого записи `@`, `www` и `grafana` указывают на адрес машины;
- наружу открыты только порты 80 и 443, их слушает Caddy. Порты сервисов из основного compose
  открыты лишь на самой машине: API, хранилище, очередь и Prometheus снаружи недоступны.

Grafana выведена на `grafana.<домен>` с анонимным просмотром — на демо это витрина метрик,
для боевого контура анонимный доступ надо выключить.

## Запуск и обновление

В `.env` рядом с `docker-compose.yml` — домен и токен доступа к правилам Матрицы:

```
DEMO_DOMAIN=<домен>
RULES_TOKEN=<токен>
```

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.demo.yml --profile monitoring up -d --build
```

Логи: `docker compose -f docker-compose.yml -f deploy/docker-compose.demo.yml logs -f worker`.

Брокер держит очереди в томе `rabbitmqdata` под постоянным именем узла, поэтому обновление
их не обнуляет.

## Настройки стенда

Всё, что зависит от контура, лежит в `.env` и в репозиторий не попадает: домен, учётные записи
(`AUTH_USERS`), лимиты загрузки, адрес и список моделей (`PIPELINE_MODEL_URL`,
`PIPELINE_MODEL_CHOICES`). Образец — `.env.example` в корне репозитория.

Без модели способ чтения «модель» понижается до распознавания, и инспектор получает
уведомление — молча прочитать иначе, чем обещано, нельзя.

## Объекты стенда

Папки объектов загружаются через сервис тем же инструментом, что и на ноутбуке:

```bash
python3 tools/upload_object.py --folder "/путь/<папка>" \
  --object-id OBJ-... --object-name "..." --login admin --password "<пароль из AUTH_USERS>"
```

С ролью `admin` загрузчик грузит без лимитов размера. С ролью `inspector` действуют
лимиты браузера, и файлы больше 50 МБ он пропустит.

После перезапуска машины контейнеры поднимаются сами (`restart: unless-stopped`), сертификаты
Caddy лежат в томе и не перевыпускаются.
