# Лицензии компонентов

Перечень сторонних компонентов, которые входят в образы поставки: `llm`, `worker`, `api`, `web`,
`postgres`, `redis`, `rabbitmq`, `minio`, `secrets`. Отдельно отмечены мониторинг (профиль
`monitoring`, в поставку не входит) и `caddy` (только облачный демо-стенд). Полный перечень —
[`components.csv`](components.csv), 551 строка: образ, компонент, версия, лицензия, прямая или
транзитивная зависимость, где закреплена версия, откуда взята лицензия. Инструменты сборки
веб-клиента (Vite, TypeScript и др.) в образы не попадают и в перечень не входят.

Внешних облачных сервисов поставка не использует: модель чтения работает в контейнере `llm`,
запасной внешний адрес модели включается только ключом, а в поставке ключа нет.

## Что это значит для комплекта

- **Локальный запуск и показ** ни одна из лицензий не ограничивает.
- **Передача архива образов** — это распространение двоичных файлов. Тексты лицензий лежат
  внутри образов: `/usr/share/doc/*/copyright`, `*.dist-info`, `node_modules/*/LICENSE`. Для
  компонентов под GPL, LGPL и AGPL исходники — у их авторов и в репозиториях Debian и Alpine.
  Эти компоненты мы не изменяли.
- **PyMuPDF** подключён к коду конвейера. По AGPL-3.0 пользователям сервиса по сети
  предлагается исходный код связанной с ним программы. Для закрытого промышленного контура нужна
  коммерческая лицензия Artifex или другая библиотека чтения PDF.
- **Redis 7.4** распространяется по RSALv2 или SSPLv1. Это не открытая лицензия по определению
  OSI, хотя локальный запуск внутреннего кеша она разрешает.

## Как собран перечень

29.09.2026. Версии прямых зависимостей взяты из `service/worker/requirements.txt`,
`service/api/package-lock.json`, `service/web/package-lock.json`, Dockerfile сервисов и тегов
образов в `docker-compose.yml` и `deploy/docker-compose.release.yml`. Транзитивные пакеты
прочитаны из собранных образов: метаданные пакетов Python, `dpkg` и `apk`. Лицензии сверены с
метаданными пакетов, `debian/copyright`, реестрами PyPI и npm и файлами LICENSE у авторов.
Образы собирались для arm64. Отличия колёс Python для amd64 (numpy, psycopg-binary) добавлены
отдельными строками. Копии одного пакета в разных местах образа (например, `certifi` внутри pip)
и разные версии во вложенных `node_modules` — отдельные строки.

Теги `postgres`, `redis`, `rabbitmq`, `node`, `nginx`, `python` и `alpine` плавающие: версии в
перечне — на дату сборки. Состав образа vLLM сверх `requirements/cuda.txt` его выпуска не
проверялся: образ не скачивался.
